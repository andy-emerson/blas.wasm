# rot — apply a plane rotation

$$(x_i, y_i) \leftarrow (c\,x_i + s\,y_i,\ \ c\,y_i - s\,x_i)$$

Six routines: `drot`, `srot` (real), `zdrot`, `csrot` (complex vectors,
real $c$ and $s$), and `zrot`, `crot` (complex vectors, real $c$,
complex $s$: $(x, y) \leftarrow (c x + s y,\ c y - \overline{s}\, x)$,
LAPACK's auxiliary rotation, since reference BLAS has no complex-sine
rotation).

```text
drot(x, y, c, s)
```

## What the result is, exactly

Each output is two multiply roundings then one add or subtract
rounding, in that order, with no fused multiply-add: bit for bit the
scalar definition on every target (tested). The complex-sine forms
compute the four products of each element in the canonical complex
product order; the products are independent, so there is no fold, and
`zrot` with a real $s$ equals `zdrot` bitwise (tested).

## How it is computed

`drot`/`srot`: an elementwise stream, two f64 or four f32 lanes,
unrolled twice. `zdrot`/`csrot`: pure delegations, since a real
rotation acts on the real and imaginary parts independently and is the
real routine over the $2n$-real view. `zrot`/`crot`: the scalar
definition per element, not streamed through the lanes, because a
rotation is applied to a pair of vectors once and the real-sine form is
the one the roofline measures.

## Performance

n = 2048, percentage of the fastest same-run memory stream, two runner
draws (the Level 1 README has the table and its provenance): f64
85–86%, f32 66–67%, c64 97–99%, c32 86–100% (the real-sine forms, which
ride the real streams).

## Tests

`tests/L1/drot.rs`, `srot.rs`, `zdrot.rs`, `csrot.rs`, `zrot.rs`,
`crot.rs`: bit-for-bit against the scalar definition at every length
through the tail; `zrot` equal to `zdrot` bitwise when $s$ is real.
