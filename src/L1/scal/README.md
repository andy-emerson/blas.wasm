# scal — scale a vector in place

$$x \leftarrow \alpha x$$

Six routines: `dscal`, `sscal` (real), `zscal`, `cscal` (complex
$\alpha$, complex $x$), and `zdscal`, `csscal` (real $\alpha$, complex
$x$, the cheaper form reference BLAS also provides).

```text
dscal(alpha, x)
```

## What the result is, exactly

One multiply rounding per element for the real forms and for the
real-$\alpha$ complex forms (each component scaled once); the full
complex product in the canonical `C64`/`C32` order for `zscal` and
`cscal`. Bit for bit the scalar definition on every target (tested).
The real-$\alpha$ form is not `zscal` with a real $\alpha$: the full
product would add a redundant $\pm 0 \cdot \mathrm{im}$ term with
signed-zero hazards, so the two round differently and reference BLAS
has both for a reason.

## How it is computed

An elementwise stream, two f64 or four f32 lanes per register,
unrolled twice. `zdscal` and `csscal` are pure delegations: a real
scale of an interleaved complex vector is `dscal`/`sscal` over the
$2n$-real view, so the tuned real stream carries over unchanged.

## Performance

n = 2048, percentage of the fastest same-run memory stream, two runner
draws (the Level 1 README has the table and its provenance): scal f64
100%, f32 100%, c64 70–75%, c32 77–78%; the real-$\alpha$ complex forms
79–83% (c64) and 93–100% (c32), riding the real stream.
