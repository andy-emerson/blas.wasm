# dot — inner product

$$x^{T} y = \sum_{i} x_i\, y_i$$

Six routines: `ddot`, `sdot` (real), `zdotu`, `cdotu` (complex,
unconjugated, $\sum x_i y_i$) and `zdotc`, `cdotc` (complex,
conjugated, $x^{H} y = \sum \overline{x_i}\, y_i$), the split reference
BLAS makes because the two are different results.

```text
ddot(x, y) -> Result<f64, Error>
```

## What the result is, exactly

A reduction's result depends on the order of its additions, and this
family's order is the lane fold: four accumulator registers (eight f64
lanes, sixteen f32 lanes) each summing every fourth register's worth
of products, folded in a fixed order at the end. That is a
legitimately different rounding sequence from the sequential sum,
equally valid, and because the order is fixed the result is the same
bits on every target. The contract is therefore an error bound against
a compensated-summation reference, plus the fold itself where a
consumer needs it: the Level 2 transposed products (`gemv_t`, the
transposed `trmv` and `trsv`) ride this fold and their tests replay it
bit for bit. The conjugated form folds the conjugated products, and
conjugation is an exact sign flip on the lanes, so `zdotc(x, y)` equals
`zdotu(conj x, y)` bitwise (tested).

## How it is computed

A reduction stream with four accumulator registers. The complex
products use the dup/swap lane form: $\mathrm{dup}_0(x) \cdot y +
\mathrm{neg}_0(\mathrm{dup}_1(x) \cdot \mathrm{swap}(y))$ for the
unconjugated product (lane 0 gets $x_r y_r - x_i y_i$, lane 1 gets
$x_r y_i + x_i y_r$) and the same with the other lane negated for the
conjugated one, each bit-exactly the canonical `C64`/`C32` product
order.

## Performance

n = 2048, percentage of the fastest same-run memory stream, two runner
draws (the Level 1 README has the table and its provenance): f64
53–57%, f32 39–43%, c64 53–57% (dotu and dotc alike), c32 46–54%. A dot
reads two arrays and writes nothing, so its honest ceiling is the read
path; against the triad the reductions sit at 73–100%.

## Tests

`tests/L1/ddot.rs`, `sdot.rs`, `zdotu.rs`, `zdotc.rs`, `cdotu.rs`,
`cdotc.rs`: error bounds against a compensated (component-wise for
complex) reference at every length through the tail; `zdotc(x, y) ==
zdotu(conj x, y)` bitwise; a length mismatch an error.
