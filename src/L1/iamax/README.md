# iamax — index of the largest element

The 0-based index of the first occurrence of $\max_i |x_i|$; for the
complex forms the magnitude is $|\mathrm{re}\,x_i| + |\mathrm{im}\,x_i|$,
reference BLAS's choice for complex pivoting (monotone enough, no
square roots). Four routines: `idamax`, `isamax`, `izamax`, `icamax`.

```text
idamax(x) -> usize
```

## What the result is, exactly

An exact index, not a rounded value: the first index attaining the
maximum, reference BLAS's tie-breaking rule; 0 for an empty slice.
NaN follows the reference: a NaN in the first element wins (index 0),
any other NaN is skipped. All of it tested exactly.

## How it is computed

Two passes: a branch-free lane-parallel `pmax` pass finds the maximum
value, then one scalar rescan finds its first index. For the complex
forms, `abs` then an add of the swapped register puts
$|\mathrm{re}| + |\mathrm{im}|$ in both lanes (addition commutes bit
exactly), so `pmax` accumulates the per-element magnitudes directly.
The two-pass shape beat the branching plain loop by 1.4–1.6× on three
runner draws; a fused single-pass variant that tracks value and index
per lane was built and raced and lost (flat on one draw, 15% slower on
the other), because the blend work per element costs more than the
rescan it saves. It is recorded so it is not re-tried without new
evidence.

## Performance

n = 2048, percentage of the fastest same-run memory stream, two runner
draws (the Level 1 README has the table and its provenance): f64
17–21%, f32 8%, c64 24–25%, c32 13–16%. The rows are priced
conservatively (two passes counted as one), and the scalar rescan
dominates: this is the level's recorded lever (`STATUS.md`), the f32
row most of all.
