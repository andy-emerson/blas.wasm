# axpy — scaled vector addition

$$y \leftarrow \alpha x + y$$

for vectors $x$, $y$ of length $n$ and a scalar $\alpha$. Four
routines: `daxpy`, `saxpy`, `zaxpy`, `caxpy`.

```text
daxpy(alpha, x, y)
```

## What the result is, exactly

Element $i$ is $\mathrm{fl}(y_i + \mathrm{fl}(\alpha x_i))$: one multiply
rounding and one add rounding, in that order, with no fused
multiply-add. The complex forms compute the complex product in the
canonical order of `C64`/`C32` ($\mathrm{re} = \mathrm{fl}(\mathrm{fl}(a_r x_r) -
\mathrm{fl}(a_i x_i))$, $\mathrm{im} = \mathrm{fl}(\mathrm{fl}(a_r x_i) + \mathrm{fl}(a_i
x_r))$) and then add, and the lane form of that product is a bit-exact
rewrite of it. Every element is independent of every other, so the
SIMD loop and its scalar tail perform exactly these roundings: bit for
bit the definition on every target, and tested as such. `daxpy`'s
module page is the full chapter of this argument, with the loop
written out.

## How it is computed

An elementwise stream: two f64 (four f32) lanes per register, unrolled
twice, the last $n \bmod 4$ elements scalar. The complex streams keep
one complex per f64 register (two per f32 register) and form the
product with the two-multiply lane form (`src/kernels.rs` describes
it): a duplicated real part times the vector, plus a duplicated
imaginary part times the swapped vector with one lane negated.

## Performance

n = 2048, percentage of the fastest same-run memory stream, two runner
draws (the Level 1 README has the table and its provenance): f64
76–77%, f32 59–68%, c64 81–83%, c32 58–60%. The f32 rows trail because
a four-lane register moves the same bytes as a two-lane one and the
loop's fixed cost is spread over fewer bytes per iteration.

## Tests

`tests/L1/daxpy.rs`, `saxpy.rs`, `zaxpy.rs`, `caxpy.rs`: bit-for-bit
against the scalar definition at every length through the tail, a
length mismatch an error. The `daxpy` chapter's example is compiled
and run by `cargo test`.
