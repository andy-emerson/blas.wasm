# symm — symmetric and Hermitian matrix multiplication

$$C \leftarrow \alpha A B + \beta C \quad(\text{left}),\qquad
C \leftarrow \alpha B A + \beta C \quad(\text{right}),$$

with $A$ symmetric (or Hermitian) and only one triangle of it stored;
the other triangle is read by reflection. Six routines: `dsymm`,
`ssymm` (real symmetric), `zhemm`, `chemm` (Hermitian: the reflected
element is conjugated and the diagonal is taken as real), and `zsymm`,
`csymm` (complex symmetric, unconjugated, as reference BLAS also
provides). $A$ is $m \times m$ on the left and $n \times n$ on the
right; $B$ and $C$ are $m \times n$. No workspace.

```text
dsymm(side, uplo, m, n, alpha, a, lda, b, ldb, beta, c, ldc)
```

## What the result is, exactly

Right side: the plain column sweep's order, $\beta c_{ij}$ then the
products added in ascending $l$ with the symmetric element looked up
across the stored triangle; the tuned shape reproduces it bit for bit
(tested by replay). Left side: each column of $C$ is a symmetric
matrix–vector product, and its contract is the fused `symv` kernel's
fold order (the Level 2 family's chapter), tested by bounds. The
Hermitian forms keep the diagonal exactly real in the sense the
reference does (the stored diagonal's imaginary part is ignored).

## How it is computed

**Left side: `symv` per column of $B$.** Column $j$ of $C$ is
$\alpha A b_j + \beta c_j$, which is exactly the Level 2 symmetric
matrix–vector product; the family rides that kernel, a fused pass that
serves both triangles from one read of each stored column.

**Right side: the four-column fan-out sweep.** Four columns of $C$ are
grouped so that each column of $B$ streams once per group (the shape
the pre-packed real gemm used, `col4`), the symmetric element fetched
by a small accessor (`dsym_at`, `zher_at` and the complex-symmetric
`zsym_at` in `src/L3/mod.rs`) that reflects across the stored
triangle and, for the Hermitian forms, conjugates on the reflected
side.

This family did **not** move onto the packing layer in the K1
campaign. It is the one real Level 3 row behind OpenBLAS-wasm by more
than the kernel can explain (below), and the obvious next candidate:
pack $A$ from both triangles into an ordinary panel and the operation
is gemm.

## Performance

**Against OpenBLAS and BLIS in the same engine** (the Level 3 README
has the table): dsymm on the left at n = 512 takes 1.24–1.27× OpenBLAS-wasm's
time (21.9–23.2 ms against 17.7–18.3) and 0.57–0.60× BLIS's.

**Against the machine** (n = 512, same-run peak probe, two draws; the
probe's defect is described in the Level 3 README): symm_left f64
81–98%, f32 75–95%; hemm_left c64 60–79%, c32 60–76%. The left side's
rate is the Level 2 `symv`/`hemv` kernel's rate; the complex hemm rows
are the lowest on the level because `zhemv`/`chemv` are the lowest
Level 2 rows.

**What is left.** Pack the symmetric $A$ as a full panel from both
triangles and run the gemm tile (the K1 machinery exists: `syrk` packs
$A$'s rows as $B$'s panel the same way). Recorded in `STATUS.md` under
"Levers"; expected to bring dsymm level with dgemm.

## Tests

`csymm.rs`: the right side replayed bit for bit against the scalar
definition, the left side bounded against a higher-precision

$\alpha = 0$ rule and the Hermitian diagonal; `errors.rs` for the
argument checks.
