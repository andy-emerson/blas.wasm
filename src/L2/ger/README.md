# ger — rank-1 update

$$A \leftarrow A + \alpha\, x\, y^{T}$$

$A$ is $m \times n$, $x$ has $m$ elements, $y$ has $n$. Six routines:
`dger`, `sger` (real), `zgeru`, `cgeru` (complex, unconjugated,
$x y^{T}$) and `zgerc`, `cgerc` (complex, conjugated, $x y^{H}$),
the split reference BLAS makes because the two are different results.

```text
dger(m, n, alpha, x, y, a, lda)
```

## What the result is, exactly

Column $j$ of $A$ gains $(\alpha y_j)\, x_i$ in each element: one
multiply for the scalar $\alpha y_j$, then per element one multiply
and one add, in that order. The conjugated form's scalar is
$\alpha\,\overline{y_j}$; the conjugation lands on the scalar, never
on a stream, so `zgerc(x, y)` equals `zgeru(x, conj y)` bitwise
(tested). Reference BLAS skips a column whose $y_j$ is exactly zero;
this crate does not, a recorded deviation (`DESIGN.md`, constraint 6;
decision D12).

## How it is computed

One Level 1 `axpy` stream per column: column $j$ of $A$ is
$y \leftarrow (\alpha y_j)\, x + y$ with the column as $y$. The rank-1
update is a pure stream (each element of $A$ read once and written
once), so this is already at the memory ceiling and no four-column
shape applies.

## Performance

n = 2048, percentage of the fastest same-run memory stream, two runner
draws (the Level 2 README has the whole table and its provenance):
f64 79–90%, f32 100%, c64 65–70% (geru and gerc alike), c32 88–92%.
The complex f64 row pays the shuffle work of the lane product form.
